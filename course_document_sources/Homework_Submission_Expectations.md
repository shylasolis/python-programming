# Textbook Homework Submission Expectations

Use this checklist with the assigned textbook exercises posted in Canvas. For **new homework assigned from the Party Roster stage onward**, these requirements and rubric weights stay the same. Publish this document before students begin. Existing homework retains its original deliverables and rubric.

## What to submit in Canvas

Submit clearly named individual `.py` files and a journal through Canvas. A folder or ZIP is also acceptable if Canvas permits it. **The journal is required for every new homework assignment from the Party Roster stage onward.**

1. **Completed Python source:** the `.py` file(s) for every required exercise, plus any small permitted sample files needed to run them.
2. **Exercise journal:** organize entries by exercise and assigned step. Briefly explain what you changed or tried, what happened when you ran or checked it, and how you responded to a problem. If it worked, say what you observed. Identify the concept or takeaway where useful.
3. **Run information in the journal:** identify the exercise numbers and filenames, Python version, dependencies if needed, and how to run each program.
4. **Testing evidence in the journal:** record the inputs/actions and results for the tests required by the exercise. Include an ordinary case and a relevant invalid-input or boundary case when applicable. Screenshots are optional unless the assignment explicitly requests them; clear written results are sufficient.
5. **AI-use note in the journal:** describe meaningful assistance, name the tool(s), explain what you requested, identify a suggestion you accepted/changed/rejected, and explain how you verified it. State if you did not use AI.

**No README is required for homework.** Keep the run information, testing notes, problem/fix or successful-check explanation, key takeaways, and AI-use/non-use note together in the homework journal. No separate AI document or testing document is required.

Submit the journal as Canvas text or an uploaded document when Canvas accepts that file type. If uploads are restricted to `.py`, use the Canvas text entry or submission comments for the journal. Do not publish homework to Git to work around upload restrictions.

If an exercise has no visible output, explain how you checked the work. You do not need to invent a problem when none occurred. Keep your explanation in your own words and be ready to explain your code.

## No Git publication requirement

**Do not publish textbook homework solutions to Git for this course.** Submit the source files and journals directly through Canvas. No repository link or public portfolio post is required for textbook homework.

Do not upload textbook PDFs, instructor solutions, classmates' work, credentials, confidential information, virtual environments, or unnecessary generated files. Use permitted textbook starter materials as directed and work on copies.

## How the homework will be graded

## Fixed homework rubric (100 points)

| Criterion | Points | Full-credit evidence |
|---|---:|---|
| Assigned code and concepts | 60 | Required exercise behavior and concepts are implemented. The Canvas task sheet allocates these 60 points among the required exercises before work begins. |
| Exercise journal | 25 | Assigned exercise/step coverage and actions (10); meaningful observations and learning (10); problem/fix or successful-check explanation and AI-use/non-use note (5). |
| Testing evidence | 10 | Ordinary and relevant invalid-input/boundary checks with inputs/actions and actual results. Use exercise-required tests where specified; if no invalid/boundary case applies, explain and give another meaningful check. |
| File organization and run information | 5 | Clearly identified exercise files and necessary sample data (2); Python version and usable run/dependency information in the journal (3). No README is required. |
| **Total** | **100** | |

These weights and deliverables remain fixed for future textbook homework. Only the exercise list, step range, due date and allocation of the 60 code points change. Do not add a Git criterion or change the journal into a different unannounced deliverable.

- Complete the specified exercises and steps, not optional enrichment unless explicitly required.
- Partial credit is available for documented attempts, debugging, and demonstrated understanding.
- Equivalent implementations are acceptable where consistent with the exercise's learning goal.
- A defect should not be counted repeatedly across unrelated categories.
- AI use itself is not a penalty; follow the assignment's allowed use and disclosure rules.
- Manual testing is acceptable unless automated tests are specifically assigned.

**Earlier-assignment exception:** the first Chapter 3 homework was journal-only. Missing source files must not reduce that assignment's grade, including its resubmissions. These new expectations do not change earlier assignments or their previously issued written-work requirements.

## Before submitting

Run each required program, check the required tests, confirm filenames match the journal/run directions, and ensure that every assigned exercise has code and written evidence.

**Assignment-specific details:** use the Canvas post for the textbook edition, exercise numbers/steps, due date, any approved accommodation, and the allocation of the 60 code points. The journal requirements and other weights above stay fixed for future homework. Where a previously issued assignment asks for a different written format, follow that assignment rather than applying this document retroactively.
