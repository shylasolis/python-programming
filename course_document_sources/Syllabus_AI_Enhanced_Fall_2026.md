## Course Description and Philosophy

This semester, we will build Python programming skills and confidence, progressing from foundational coding mechanics to practical applications. This is an interactive, AI-enhanced course. Artificial intelligence may support debugging, help explore alternatives, and personalize practice after foundational skills have been attempted and understood.

Students should treat their work as the development of professional skills and, where appropriate, portfolio artifacts. The goal is not merely to finish an assignment: it is to create, test, explain, document, and improve programs.

## Learning and Assessment Activities

Students will complete four kinds of work:

- **In-class activities:** Guided programming activities used to practice and demonstrate weekly concepts.
- **Weekly homework:** Individual practice, often connected to textbook exercises, with written reflection or testing evidence when assigned.
- **Individual book-topic teaching activity:** Each student chooses a topic from the weekly schedule, studies the related textbook material, and builds a Python-based activity in Git that helps classmates understand and practice the concepts.
- **Final application project:** Each student proposes and builds a Python application that uses course skills and can be presented as a professional portfolio artifact.

## Submission Expectations

### Textbook Homework

Submit textbook homework through Canvas as the requested Python source files and written work (for example, a journal, test notes, or reflection). Git is encouraged for version history and learning, but a public Git repository is not required for textbook exercises. Students may use a private practice repository.

### In-Class Activities

Maintain in-class programming activities in Git as professional project repositories. Submit the repository link through Canvas using the instructor's directions. Include a README with the project purpose, setup/run instructions, and any special instructions. Include a `requirements.txt` when the program uses third-party Python packages; when it uses only the standard library, state the Python version and run command in the README instead.

Repositories must not contain passwords, API keys, or private personal information. Follow instructor directions for repository visibility and granting access. If a repository link cannot be accessed by the grader, the student may be asked to provide an approved Canvas archive or correct access.

### Final Project

Maintain the final application in Git and submit its repository link through Canvas. The project repository must include a professional README, setup/run instructions, appropriate dependency information, testing evidence, and an AI-use statement. Final project instructions will specify milestones, presentation/demo expectations, and the final rubric.

### Canvas and Repository Access

Canvas is the official submission channel for assignment links, requested files, written work, and grade feedback. Git is the version-control and project-documentation space for in-class activities and the final application. Unless explicitly approved, do not publish student work publicly. Use the course-approved repository platform and access settings.

## Artificial Intelligence Use

AI may be used as a learning and development aid when an assignment permits it. Students remain responsible for their submitted work and should be able to explain and verify it. Follow the specific AI instructions on each assignment.

When asked, disclose meaningful AI assistance by stating the tool used, what help was requested, what suggestion was used or changed, and how the result was checked. Do not submit generated code or explanations you cannot explain. Do not share passwords, API keys, private records, or other sensitive information with AI tools. Verify factual claims and test code rather than assuming AI output is correct.

The course also introduces AI agents: systems that can use tools or take bounded steps toward a goal. Students will consider permissions, privacy, reliability, verification, and human oversight when using or designing agent-based workflows.

## Professional Git Practice

For repositories required by an assignment:

- Use clear filenames and an understandable folder structure.
- Commit meaningful increments as work progresses; do not leave all work as one unexplained final commit.
- Write a README for a new reader that explains what the project does and how to run it.
- Include only necessary dependencies and project files.
- Keep credentials and private information out of the repository.
- Credit external code, data, and assets according to their license and the assignment directions.

## Final Application Project

Each student will propose and develop a Python application that creates value for a defined user or need. The application should be achievable within the course timeline, demonstrate course skills, handle relevant inputs and edge cases, and include testing and professional documentation. Students will submit the project proposal, checkpoints, repository, README, and final demonstration/reflection as described in the Final Project instructions.

## Individual Book-Topic Presentation

Each student chooses a topic represented in the weekly schedule, studies the corresponding textbook material until they can explain it, and creates an engaging Python-based learning activity for classmates. The activity should help peers understand and practice the selected concepts, not just watch a demonstration. Build the activity in a Git repository with a README that lets a classmate set it up, run it, and follow the instructions independently. Test those directions with a peer before presenting. Submit the repository link through Canvas and cite the textbook chapter and printed pages. See the book-topic teaching activity instructions for requirements and rubric.
